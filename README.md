## Апаратний стенд

- Мікроконтролер: **ESP32-S3 DevKit**.
- Датчик відстані: **US-100**.
- Інтерфейс взаємодії з прошивкою: UART.
- Параметри UART: `115200 8N1`.
- Об'єкт перед датчиком: приблизно **20 см**.

### Роль ESP32-S3

ESP32-S3 є **DUT — Device Under Test**

- отримує команди через UART;
- керує датчиком US-100;
- виконує вимірювання відстані;
- обробляє alarm-логіку;
- повертає результати й діагностичні повідомлення через serial console

### Роль US-100

US-100 — ультразвуковий модуль вимірювання відстані. Він не є окремим DUT у цьому проєкті, а виступає зовнішнім сенсором, від якого ESP32-S3 отримує дані.

Для тестів використовується реальний стабільний об'єкт, розташований приблизно за 20 см від датчика. Це дозволяє перевіряти порогову логіку без симуляції показань:

- threshold `50`, `30`, `20` см — очікується `TRIGGERED`;
- threshold `10`, `5` см — очікується `ARMED`;
- зона `near` та `custom 15 25` — очікується `TRIGGERED`;
- зона `far` та `custom 25 35` — очікується `ARMED`.

## Assertions і якість перевірок

Під час розробки тестів я намагався використовувати не одну загальну перевірку, а кілька assertions на різних етапах сценарію.

Наприклад, alarm-тести окремо перевіряють:

- що sensor mode встановлено в `distance`;
- що distance alarm або zone успішно налаштовані;
- що alarm переведено в стан `ARMED`;
- що sensor успішно запущено;
- що фінальний стан відповідає `TRIGGERED` або `ARMED`.

Це допомагає точніше локалізувати помилку. Якщо тест падає, зрозуміло, чи проблема виникла під час налаштування режиму, активації alarm, запуску сенсора або під час самої перевірки стану.

У тестах також використовуються:

- зрозумілі assertion messages;
- constants замість magic numbers і magic strings;
- `casefold()` для нечутливого до регістру пошуку текстових markers;
- shared helpers для обробки UART-відповідей;
- параметризація pytest для повторного використання сценаріїв.


## Налаштування змінних середовища

Назву COM-порту в коді не задано. Порт автоматично знаходиться через USB VID, приклад змінних середовиза:

```powershell
$env:ESP32_VID="0x403"
$env:DUT_LOGIN="<логін>"
$env:DUT_PASSWORD="<пароль>"
```
